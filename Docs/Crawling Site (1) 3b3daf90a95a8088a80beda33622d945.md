## 1. Rust Crawler Plugin Architecture

대규모 소스(60개 이상)를 확장성 있게 관리하기 위해 **동적 라이브러리(`dylib`) 또는 WebAssembly(Wasm)** 기반의 플러그인 구조를 채택하고, 코어 엔진은 비동기 파이프라인으로 처리합니다.

### 🔌 아키텍처 핵심 구성 요소

- **Core Engine (`tokio` + `reqwest`)**: 스케줄링, Rate Limiting, 에러 핸들링, 프록시 로테이션 및 공통파이프라인 관리.
- **Plugin Interface (`abi_stable` 또는 `wasmtime`)**: 각 소스별 크롤링 로직을 표준화된 인터페이스로 분리.
- **Queue & Buffer (`Channel` / `Kafka`)**: 수집된 원본 데이터를 정규화 단계로 넘기는 비동기 버퍼.

### 📂 디렉토리 구조

```
ai-research-crawler/
├── crawler-core/          # 코어 엔진 (스케줄러, DB 적재, 공통 구조체)
├── crawler-plugins/       # 개별 소스 플러그인 디렉토리
│   ├── plugin-arxiv/      # arXiv 수집 플러그인
│   ├── plugin-semantic/   # Semantic Scholar 수집 플러그인
│   └── ... (총 60개)
└── common-interface/      # 플러그인과 코어가 공유하는 데이터 트레이트(Trait)
```

### 🦀 핵심 Rust 코드 예시 (Trait 정의)

Rust

```
use async_trait::async_trait;
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, Debug)]
pub struct RawDocument {
    pub source_id: String,
    pub title: String,
    pub abstract_text: String,
    pub authors: Vec<String>,
    pub published_date: String,
    pub url: String,
    pub raw_metadata: serde_json::Value,
}

#[async_trait]
pub trait CrawlerPlugin: Send + Sync {
    /// 플러그인 고유 이름 (예: "arxiv", "semantic_scholar")
    fn name(&self) -> &str;

    /// 대상 소스에서 최신 연구 문서 크롤링 수행
    async fn fetch_documents(&self, limit: usize) -> Result<Vec<RawDocument>, Box<dyn std::error::Error>>;
}
```

## 2. Neo4j Ontology 설계 (AI Research Knowledge Graph)

수집된 60개 소스의 파편화된 데이터를 통합하고, 논문 간의 인용 관계, 연구자, 핵심 개념(Concept)을 다차원으로 엮기 위한 **그래프 온톨로지(Graph Ontology)** 구조입니다.

### 📌 Node Labels (노드 정의)

- `(:Paper {id, title, abstract, publishedDate, url})`
- `(:Author {id, name, affiliation})`
- `(:Source {id, name, sourceType})` (예: arXiv, IEEE 등 수집처)
- `(:Concept {id, name, category})` (예: Large Language Models, Graph RAG 등)
- `(:Institution {id, name})` (대학, 연구소 등)

### 🔗 Relationship Types (관계 정의)

- `(:Author)-[:AUTHORED]->(:Paper)`
- `(:Paper)-[:CITES]->(:Paper)`
- `(:Paper)-[:COLLECTED_FROM]->(:Source)`
- `(:Paper)-[:HAS_CONCEPT]->(:Concept)`
- `(:Author)-[:AFFILIATED_WITH]->(:Institution)`

```
[60개 AI 소스]
```

## 4. Neo4j 적재용 Cypher 쿼리 예시

Rust 크롤러가 데이터를 정제한 뒤 Neo4j에 안전하게 Upsert(병합)하는 대표적인 Cypher 패턴입니다.

Cypher

```
MERGE (s:Source {id: $source_id})
MERGE (p:Paper {id: $paper_url})
ON CREATE SET p.title = $title, p.abstract = $abstract_text, p.publishedDate = $published_date, p.url = $url
MERGE (p)-[:COLLECTED_FROM]->(s)

FOREACH (author_name IN $authors |
  MERGE (a:Author {name: author_name})
  MERGE (a)-[:AUTHORED]->(p)
)

FOREACH (concept_name IN $concepts |
  MERGE (c:Concept {name: concept_name})
  MERGE (p)-[:HAS_CONCEPT]->(c)
)
```
