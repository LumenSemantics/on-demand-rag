# 시행착오 · 트러블슈팅 기록

AIRP(AI 연구 인텔리전스 플랫폼) 구축 과정에서 발생한 문제를 **발생 순서대로** 정리한다.
각 항목: **발생 현상 → 발생 원인/이유 → 해결 방법**.

---

## 1단계 · 개발 환경 구축

| # | 발생 현상 | 발생 원인 / 이유 | 해결 방법 |
|---|-----------|------------------|-----------|
| 1 | `uv`의 `.venv` 생성/삭제가 `os error 5 (액세스 거부)`로 실패 | 프로젝트가 **OneDrive 동기화 폴더** 안에 있어 OneDrive가 `.venv` 파일을 잠금 | 프로젝트를 OneDrive 밖(`C:\Users\sally\Documents\AIRP`)으로 이동, 손상된 `.venv` 삭제 후 재생성 |
| 2 | Edit로 수정한 내용이 반영 안 되거나 엉뚱한 파일이 수정됨 | 편집 툴이 **이동 전 OneDrive 경로**를 계속 추적 | 새 경로 기준으로 `sed`/`bash`를 사용해 재적용 |

## 2단계 · LLM·설정

| # | 발생 현상 | 발생 원인 / 이유 | 해결 방법 |
|---|-----------|------------------|-----------|
| 3 | Gemini 호출이 **404(모델 없음)** | `gemini-2.0-flash`·`gemini-2.5-flash`·`text-embedding-004` 등 지정 모델이 폐기/비가용 | `ListModels`로 사용 가능 모델 확인 → LLM은 `gemini-flash-lite-latest`, 임베딩은 `gemini-embedding-001`로 교체 |
| 4 | `LLM_PROVIDER`가 인식되지 않고 빈 값 취급 | `.env`에서 `LLM_PROVIDER=gemini # 주석`처럼 **같은 줄 주석**을 dotenv가 값의 일부로 읽음 | 주석을 **별도 줄**로 분리 + `config`에서 provider 화이트리스트(`openai/anthropic/gemini`) 검증 |
| 5 | `ruff` 경고 **E501(줄 길이 초과)** 가 계속 발생 | HTML 템플릿·정규식 분류 테이블이 한 줄로 길어 불가피 | `pyproject.toml`에 파일별 `per-file-ignores`(`airp/api/app.py`, `airp/catalog.py`) 추가 |

## 3단계 · Stage 2 클라우드 연결 (Neo4j · Qdrant)

| # | 발생 현상 | 발생 원인 / 이유 | 해결 방법 |
|---|-----------|------------------|-----------|
| 6 | Neo4j 연결 실패: `Unable to retrieve routing information` / `self-signed certificate in certificate chain` | Windows Python이 시스템 CA 번들을 찾지 못해 **TLS 검증 실패** | `graph.py` 상단에 `os.environ.setdefault("SSL_CERT_FILE", certifi.where())` 추가 |
| 7 | Neo4j `AuthError` (인증 실패) | `.env`의 **비밀번호가 잘못 복사**됨 | Aura가 발급한 자격증명 파일에서 정확한 값을 확인해 교체 |
| 8 | Neo4j 접속이 **DNS 실패** | Aura 인스턴스를 재생성해 옛 호스트가 삭제됨(구 `58893efb` 삭제 → 신 `f2af99db` 활성) | 살아있는 인스턴스의 자격증명으로 `NEO4J_URI/USER/PASSWORD` 갱신 |

## 4단계 · 지식 질의 (Cypher)

| # | 발생 현상 | 발생 원인 / 이유 | 해결 방법 |
|---|-----------|------------------|-----------|
| 9 | 관련문서·그래프 결과의 **제목이 빈 문자열** | `coalesce(title_ko, title)`가 빈 문자열 `""`을 유효값으로 반환 | Cypher를 `CASE WHEN o.title_ko <> '' THEN o.title_ko ELSE o.title END`로 변경 |
| 10 | 트렌드의 **카테고리가 항상 비어 있음** | category가 문서 속성이 아니라 별도 `Category` **노드** | `(d)-[:HAS_CATEGORY]->(c:Category)` 관계로 조회하도록 수정 |

## 5단계 · 알림 (KakaoTalk · Email)

| # | 발생 현상 | 발생 원인 / 이유 | 해결 방법 |
|---|-----------|------------------|-----------|
| 11 | 카카오 API `KOE101` | 앱에 **카카오 로그인**이 활성화되지 않음 | 카카오 개발자 콘솔에서 카카오 로그인 **ON** |
| 12 | 카카오 API `KOE010` | **Client Secret이 활성 상태**라 코드 없이 호출 불가('재발급'은 비활성화가 아님) | Client Secret을 **비활성화**하고 저장 |
| 13 | 카카오 **403 insufficient scopes** | `talk_message` 동의 항목 누락 | 앱 연결을 **해제 후 재동의**(talk_message 포함) |
| 14 | Gmail(SMTP) 발송 실패 | 2단계 인증 계정에 **일반 비밀번호**를 사용 | Gmail **앱 비밀번호**를 발급해 `SMTP_PASSWORD`에 설정 |

## 7단계 · Google Cloud Run 배포

| # | 발생 현상 | 발생 원인 / 이유 | 해결 방법 |
|---|-----------|------------------|-----------|
| 17 | 첫 배포가 **europe-west1(벨기에)** 로 생성됨 | 리전 기본값을 서울로 변경하지 않음(리전은 생성 후 변경 불가) | 서비스 삭제 후 **asia-northeast3(서울)** 로 재생성 |
| 18 | 서비스 이름 `AIRP` 저장 시 빨간 오류 | Cloud Run 이름은 **소문자·숫자·하이픈**만 허용(대문자 불가) | 이름을 `airp`로 변경 |
| 19 | 배포됐지만 검색·AI가 **HTTP 500**, 트렌드는 빈 결과 | **환경변수 0개** — Qdrant/Neo4j/Gemini 접속정보 미주입(Gemini는 `key=`가 빈 상태로 403) | 10개 환경변수를 Cloud Run에 주입(`gcloud run services update` 또는 콘솔 '변수 및 보안') |
| 20 | 트렌드는 되는데 검색만 Neo4j **인증 실패** | `NEO4J_USER`에 통상값 `neo4j`를 넣음. 이 Aura 인스턴스의 실제 사용자명은 **인스턴스 ID `f2af99db`** | `NEO4J_USER=f2af99db`로 설정 (로컬 연결로 검증) |
| 21 | 검색 500: `UnicodeEncodeError: 'ascii' ... position 8-175` (Qdrant 클라이언트) | 긴 `QDRANT_API_KEY`를 **채팅에서 복사**할 때 렌더링이 비ASCII 숨은 문자(소프트하이픈 `U+00AD`)를 삽입 | 깨끗한 **텍스트 파일**에서 복사해 콘솔 **단일 필드**에 붙여넣기(명령줄 대신) |
| 22 | 로컬 테스트에서 `/healthz`가 구글 404 | 실제 앱 404가 아니라 **테스트 환경(샌드박스 프록시)** 이 그 경로를 가로챈 아티팩트(FastAPI 404는 JSON) | 실제 문제 아님 — 루트·기타 API 정상으로 배제(배포 이미지엔 라우트 존재) |
| 23 | Cloud Shell에 `-bash: command not found` 대량 발생 | 로그 텍스트 전체를 **터미널에 붙여넣어** 명령으로 해석됨 | 로그는 붙여넣지 말고 **파일로 다운로드**해 공유 |

## 8단계 · 명칭 통일 · 알림 개편 · 운영

| # | 발생 현상 | 발생 원인 / 이유 | 해결 방법 |
|---|-----------|------------------|-----------|
| 24 | 패키지 리네이밍(`arip→airp`) 중 `uv sync`가 `os error 32`(파일 사용 중)로 실패 | 실행 중이던 `arip-api` 웹 서버 프로세스가 `.exe`를 잠금 | 해당 서버 프로세스 종료 후 재sync (리네임·동기화 전 실행 중 서버 정리) |
| 25 | 일일 브리핑의 **Gmail·카카오가 수신 안 됨**(Slack은 정상) | Actions는 `.env`가 아닌 **GitHub Secrets** 사용 — 이메일·카카오 시크릿 누락/오타/만료. 발송이 `try/except`라 잡은 "성공"으로 끝나 조용히 실패 | 로컬에서 자격증명 검증(SMTP 로그인·카카오 토큰) → GitHub Secrets 설정/갱신 |
| 26 | 카카오 발송이 **반복적으로 실패** | 카카오 `refresh_token`이 주기적으로 만료·회전 → 저장 값이 자주 무효화 | 유지보수 부담으로 **카카오 발송 비활성화**(코드·워크플로 주석) 후 **텔레그램**으로 전환 |
| 27 | 텔레그램 봇 `getUpdates`에 **chat_id가 안 잡힘**(0건) | `@BotFather`(봇 **관리**봇)에 메시지를 보냄 — 실제 봇(`@ysjAIR_bot`)엔 미전송 | 실제 봇을 **`t.me/<username>` 딥링크**로 열어 메시지 전송 → chat_id 확보 |

## 반복된 패턴 · 재발 방지 교훈

| 패턴 | 교훈 |
|------|------|
| **환경/경로** | 동기화 폴더(OneDrive) 밖에서 가상환경 사용. 도구가 옛 경로를 추적할 수 있으니 이동 후 경로 확인. |
| **자격증명 복사 손상** | 긴 토큰(API 키/JWT)은 **채팅·렌더링 화면에서 복사 금지** → 원본 파일·대시보드에서 복사. 짧은 값은 무사해도 긴 값은 숨은 문자가 섞일 수 있음. |
| **관리형 서비스 기본값** | Aura 사용자명이 `neo4j`가 아닐 수 있음, Cloud Run 리전/이름 규칙 등 **기본값을 항상 실제 값으로 검증**. |
| **모델 버전 폐기** | LLM/임베딩 모델명은 수시로 폐기됨 → 하드코딩 대신 `ListModels`로 확인. |
| **설정 파서 함정** | dotenv는 같은 줄 주석을 값으로 읽음 → 주석은 별도 줄 + 코드에서 값 검증. |
| **배치 상태 유지** | 무상태 실행 환경(Actions/Cloud Run)에서는 `seen.db` 같은 상태를 캐시/볼륨으로 명시적으로 유지. |
| **클라우드 디버깅** | 로그는 **파일로 내려받아** 확인(터미널 붙여넣기 금지). 로컬 재현으로 "값 손상 vs 코드/버전" 구분. |
| **알림 채널 점검** | 발송은 예외를 삼켜 **조용히 실패** → 정기 **수동 실행(Run workflow)** 으로 실제 수신 확인. 토큰(카카오·텔레그램) 만료/회전 주의. |
| **봇 vs 관리봇** | 텔레그램은 `@BotFather`(생성·관리)와 실제 봇이 별개. 실제 봇은 이름 검색이 아니라 **`t.me/<유저네임>` 딥링크**로 연다. |
| **리소스 잠금** | 리네임·동기화·재설치 전, 실행 중인 서버/프로세스를 먼저 종료(파일 잠금 `os error 32` 방지). |
